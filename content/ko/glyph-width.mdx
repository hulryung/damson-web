# 기호와 한글 폭

터미널은 문자를 일정한 격자에 놓지만 글꼴의 실제 그림 폭은 다를 수 있습니다. D2Coding 같은 한글 글꼴은 원문자 ①…⑳, Ⓐⓐ, ※, ★, 화살표를 일반 문자보다 넓게 그립니다. 반면 앱과 유니코드 폭 규칙은 이 중 일부에 한 칸을 할당합니다.

## 서로 다른 세 가지 처리

| 처리 | 대상 | 격자 | 표시 방식 | 표 정렬에 영향 |
| --- | --- | --- | --- | --- |
| 두 칸 크기 아이콘, 기본 켜짐 | Nerd Font 아이콘 | 1칸 | 중심을 맞춰 본래 크기로 표시 | 없음 |
| 전각 디자인 자연 크기, 자동 | 원문자 등 모호한 폭의 기호 | 1칸 | 오른쪽이 비면 원래 크기, 차 있으면 축소 | 없음 |
| 모호한 폭을 두 칸으로, 기본 꺼짐 | 같은 기호 | 2칸 | 항상 원래 크기 | 있음 |

## 두 칸 크기 아이콘

**설정 → 모양 → Double-width icons**는 기본적으로 켜져 있습니다. `Nerd Font Mono`가 아닌 글꼴의 큰 아이콘을 한 칸 중심에 맞춰 두 칸 크기로 그립니다. 격자는 그대로 한 칸이므로 커서와 열 계산은 바뀌지 않습니다. 바로 옆 텍스트와 그림이 겹칠 수 있으며, 옵션을 끄면 칸에 맞게 줄어듭니다.

Powerline 구분자는 이 옵션과 관계없이 칸 가장자리에 맞춰 그려 연결부가 벌어지지 않게 합니다.

## 전각 기호의 자연 크기 표시

유니코드가 동아시아 모호한 폭으로 분류한 원문자, 별, 화살표와 도형은 일반적으로 `wcwidth`에서 한 칸입니다. 한글 글꼴은 약 1.7칸 크기로 그리기도 합니다.

- 오른쪽이 비어 있으면 본래 크기로 그립니다. `① 항목`에서 원문자가 크게 보입니다.
- 오른쪽에 문자가 있으면 칸에 맞게 줄입니다. `①②③`이 서로 겹치지 않습니다.

격자는 항상 한 칸이므로 정렬 규칙은 바뀌지 않습니다. 원래 한 칸 크기인 영문 코딩 글꼴은 영향이 없습니다.

## 모호한 폭의 기호를 두 칸으로

**설정 → 모양 → Ambiguous-width symbols as double width**는 기본적으로 꺼져 있습니다. 켜면 해당 기호에 실제 두 칸을 할당하므로 연속 원문자도 줄어들지 않습니다.

앱이 `wcwidth`나 `string-width`로 한 칸이라 계산하면 표의 오른쪽 테두리가 어긋날 수 있습니다. 셸의 줄 편집에서도 화면의 커서 위치와 계산이 달라질 수 있습니다. 상자 그리기 문자 `─ │ ┌ ┐`와 일반 문장부호는 제외하여 표 틀 자체의 폭은 유지합니다.

- 표를 그리는 TUI를 주로 사용하면 **꺼짐**을 권장합니다.
- 한글·일본어 문서와 로그에서 전각 기호를 크게 읽으려면 **켜짐**을 고려하세요.
- Vim에서는 `set ambiwidth=double`로 맞출 수 있습니다. Emacs에도 관련 설정이 있습니다. Node 기반 TUI는 조정이 어려운 경우가 많습니다.

설정 변경은 새로 출력되거나 앱이 다시 그린 행에 적용됩니다.

## 대체 글꼴 순서

격자 폭과 어떤 글꼴로 그릴지는 독립적입니다.

1. 사용자가 선택한 글꼴
2. 설치되어 있다면 지정된 CJK 대체 글꼴, D2CodingLigature Nerd Font Mono
3. 이모지용 Apple Color Emoji
4. CoreText가 선택한 시스템 대체 글꼴

기본 글꼴에 없는 원문자도 대체 글꼴로 표시합니다. 적절한 글꼴이 전혀 없다면 빈 상자 모양이 나타날 수 있습니다.
