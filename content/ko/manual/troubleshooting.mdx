# 문제 해결

## command not found

[CLI 준비](/ko/manual/installation#cli-준비)의 PATH 설정을 적용하세요. 절대 경로로 `--help`가 실행된다면 앱 설치가 아니라 PATH 문제입니다. 앱을 옮기거나 오래된 CLI를 복사해 사용한 경우 경로와 버전을 함께 확인합니다.

## 실행 중인 Damson을 찾지 못함

Damson 앱을 연 뒤 `damson-cli --list-instances`로 조회합니다. 여러 인스턴스가 있으면 `--pid`를 지정하세요. 종료된 앱의 PID와 분할 창 ID는 다시 조회해야 합니다.

## 에이전트가 열린 채로 진행하지 않음

해당 pane에서 로그인·권한 승인·프로젝트 신뢰 질문이 있는지 확인합니다. **Settings → Agents**에서 선택한 명령이 일반 셸에서도 실행되는지 확인하세요. 오래 조용하다는 상태만으로 실제 작업 진행을 판단할 수 없습니다.

Claude 외 도구의 “사용자 대기” 알림은 지원되지 않습니다. Claude의 `idle` 알림도 작업 완료 판정은 아닙니다. 결과 파일과 테스트를 직접 확인하세요.

## workflow validate가 실패함

JSON의 필드명, 중복 ID, 존재하지 않는 의존성, 순환 의존성을 확인합니다. `cwd`의 상대 경로는 현재 셸이 아니라 계획 파일 위치를 기준으로 합니다. prompt 작업에는 `verify`가 필요합니다. [필드 설명](/ko/manual/workflows#계획의-주요-필드)을 참고하세요.

## 워크플로가 실패하거나 다음 작업이 시작되지 않음

`damson-crew workflow status --state .crew/run-1`과 해당 state 폴더의 로그를 확인합니다. 선행 작업 실패, 검증 실패, 누락된 출력, 시간 초과를 구분하세요. 계속 실행되는 개발 서버를 유한한 작업으로 넣지 않았는지도 확인합니다.

중단한 실행을 재개할 때는 원래 계획과 같은 state를 사용합니다. 계획을 변경하려면 기존 worker 상태를 확인하고 별도 실행으로 준비해야 합니다. 자세한 동작은 [중단·재개](/ko/manual/workflows#중단재개와-실패-확인)를 참고하세요.

## worktree가 삭제되지 않음

수정·미추적 파일, 다른 그룹이나 앱 인스턴스의 사용, 소유권 기록을 확인합니다. 필요한 변경을 저장하고 사용 중인 작업을 마친 뒤 원래 tasks 파일로 정리 명령을 재실행하세요. 사용자 worktree가 보존되는 것은 의도된 동작입니다.

## 재실행했지만 이전 프로그램이 종료됨

일반 Quit과 앱 충돌은 실행 중인 세션 유지 대상이 아닙니다. **Terminal → Sessions** 설정과 종료 방식을 확인하세요. [세션 유지 범위](/ko/manual/terminal#재시작해도-작업을-유지하려면)에 모드·시간 제한이 설명되어 있습니다.

## Computer Control 메뉴가 없음

v0.8.0부터 포함됩니다. 이전 버전이라면 업데이트하고 **Tools → Computer Control…**를 확인하세요. 권한 목록에서 앱을 찾지 못하면 [데스크톱 제어 설정](/ko/manual/computer-control)의 실제 보조 앱 경로 안내를 따르세요.

## 문제 신고

[GitHub Issues](https://github.com/hulryung/damson/issues)에 앱 버전, macOS 버전, 재현 단계, 기대 동작과 실제 결과를 남겨 주세요. CLI 문제는 실행 명령과 종료 코드, workflow 문제는 민감한 내용을 제거한 계획과 실패 로그를 함께 제공하면 재현에 도움이 됩니다.
