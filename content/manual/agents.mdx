# 여러 에이전트 실행

`damson-crew run`은 작업마다 에이전트를 실행하고 탭을 그룹으로 묶습니다. 사람이 각 에이전트와 대화하며 진행할 때 사용합니다. 작업 완료를 검증하고 다음 단계를 자동으로 시작하려면 [managed workflow](/manual/workflows)를 사용하세요.

## 작업 목록 만들기

아래 내용을 `tasks.json`으로 저장하고 폴더 경로와 요청 내용을 바꾸세요. `cwd` 폴더는 미리 존재해야 하며 `repo`는 기존 Git 저장소여야 합니다.

```json
[
  {
    "name": "review-api",
    "cwd": "~/dev/api",
    "prompt": "인증 변경을 검토하고 문제점과 검증 방법을 정리해줘."
  },
  {
    "name": "fix-parser",
    "repo": "~/dev/core",
    "branch": "agent/fix-parser",
    "command": ["codex"],
    "prompt": "실패하는 파서 테스트를 재현하고 수정한 뒤 테스트를 실행해줘."
  }
]
```

`command`를 생략하면 Agents 설정의 기본 명령을 사용합니다. `repo`를 지정한 작업은 별도 Git worktree에서 실행됩니다. 같은 목록 안의 `name`은 서로 달라야 합니다.

## 실행하고 상태 확인하기

```sh
damson-crew run --tasks tasks.json --group refactor
damson-crew watch --tasks tasks.json --notify --focus
```

같은 그룹의 같은 작업을 다시 실행하면 기존 탭에 연결합니다. `--focus`는 응답이 필요한 pane을 앞으로 가져옵니다. 감시 명령을 Ctrl-C로 끝내도 열린 작업 탭은 남습니다.

현재 **대기 상태 감지와 알림은 Claude Code만 지원**합니다. 다른 도구도 실행·그룹화할 수 있지만 “사용자 응답 대기” 알림을 동일하게 제공하지는 않습니다. `idle`은 에이전트가 멈췄다는 신호이며 결과물 완성을 보장하지 않습니다.

## 실행 동작 설정

**Settings → Agents**에서 기본 명령, Claude 승인 생략, 대기·종료·장시간 정체 알림, 대기 탭 앞으로 가져오기, worktree 생성 위치와 신뢰 설정을 조정합니다. Claude 승인 생략이 켜져 있으면 파일 수정과 명령 실행을 매번 묻지 않습니다.

## 작업 종료와 정리

결과물을 확인하고 필요한 변경을 저장한 후 그룹을 닫으세요. 아래 명령은 그룹 안의 실행 중인 프로그램도 종료합니다.

```sh
damson-crew close --group refactor --yes
```

생성한 worktree까지 정리하려면 원래 작업 목록을 함께 지정합니다.

```sh
damson-crew close --tasks tasks.json --group refactor --remove-worktrees --yes
```

수정·미추적 파일이 남아 있거나 다른 그룹·인스턴스에서 사용 중인 worktree는 보존됩니다. 사용자가 만든 worktree도 자동 삭제하지 않습니다. 정리에 실패하면 원인을 해결한 뒤 같은 명령으로 다시 시도할 수 있습니다.

## Claude에서 오케스트레이션 스킬 사용

Claude Code가 설치되어 있다면 다음과 같이 플러그인을 등록합니다.

```sh
claude plugin marketplace add hulryung/damson
claude plugin install damson-orchestration@damson
```

플러그인을 불러온 Claude 세션에서 “Damson 오케스트레이션으로 게임을 만들어줘. 구현을 나누고 통합 테스트와 실행 확인까지 진행해줘”처럼 요청합니다. 스킬이 계획과 검토를 담당하고 `damson-crew`가 실행을 담당합니다. 앱 업데이트와 플러그인 업데이트는 별도입니다.

[Orchard](/orchard)는 별도 앱입니다. Damson에 포함된 crew로 작업을 실행하기 위해 Orchard를 설치할 필요는 없습니다.
